The merger is responsible for combining JSON Schema definitions, merging `allOf` compositions,
and applying schema defaults to form data.

```typescript
export interface Merger {
  mergeSchemas(a: Schema, b: Schema): Schema;
  /**
   * Merges schema and its `allOf` schemas into a single schema
   */
  mergeAllOf(schema: Schema): Schema;
}

export interface MergeFormDataAndSchemaDefaultsOptions {
  schema: Schema;
  formData: SchemaValue | undefined;
  initialDefaultsGenerated?: boolean;
  includeUndefinedValues?: boolean | "excludeObjectChildren";
}

export interface FormValueChange {
  path: FieldPath;
  /**
   * A snapshot of the value at `path` before the change. Later in-place writes
   * must not alter it.
   */
  oldValue: FieldValue;
  /**
   * Whether `path` had an own value before the change. A `false` value means
   * the change created the entry, so replaying the change removes it instead
   * of writing an own `undefined`.
   *
   * Callers that construct a change by hand may omit this; it is then treated
   * as `true`.
   */
  hadOwnValue?: boolean;
}

export interface FormMerger extends Merger {
  /**
   * Merges defaults of `schema` into `formData`
   */
  mergeFormDataAndSchemaDefaults(
    options: MergeFormDataAndSchemaDefaultsOptions
  ): SchemaValue | undefined;
}
```

Use `createFormMerger` from `@sjsf/form/mergers/modern` for most projects.
The legacy merger is available for v2 compatibility.

The merger only combines schemas and applies defaults. Comparing values and
copying them before an in-place update is the job of the
[value handler](/form/value-handler/), which is a separate required option.

The stale-defaults pass described in the
[dynamic forms guide](/guides/dynamic-forms/#branch-defaults) computes each
branch's defaults through `mergeFormDataAndSchemaDefaults`, so a custom merger
needs no extra method: implement it as usual and the pass follows the same
defaults.
