  ValidationResult<Output>,

// Internal value store; use the value queries and commands.

  replace(value: FormValue): void;

`CoreContext` holds the dependencies every core schema helper needs. The
dependencies are stored under internal symbols, so a `FormState` can satisfy
the interface without exposing them as public properties. The `CORE_*` symbols
shown above are not part of the `@sjsf/form/core` entry point; import them from
`@sjsf/form/core/internals` if you build or inspect a context directly. The
helpers read them through the free functions
`isValid(ctx, schema, value)`, `mergeSchemas(ctx, a, b)`,
`mergeAllOf(ctx, schema)`, `isValueDeepEqual(ctx, a, b)`,
`resolveRef(ctx, ref)`, and `getRootSchema(ctx)`.

Call `createCoreContext({ validator, merger, rootSchema })` to build a standalone
context for a core helper when you do not have a `FormState`. Every core helper
that needs these dependencies takes the context as its first argument, for
example `retrieveSchema(ctx, schema, formData)` or
`getDefaultFormState(ctx, schema, formData)`.

## Methods

SJSF provides a set of functions to work with the form state that can either **read** (queries) or **modify** (commands) it.

:::note
Most of these methods are intended for **internal use** within form components.
:::

:::note
All the methods listed below are marked with `@query` or `@command` in their JSDoc.
:::

**Queries:**
`getComponent`, `getFieldComponent`, `getStableConfig`, `getFieldErrors`,
`getFieldsErrors`, `hasErrors`,
`getErrors`, `hasFieldState`, `getId`, `getSubtreePaths`,
`getChildPath`, `getPseudoPath`, `getPseudoId`,
`isSelect`, `isMultiSelect`, `isFilesArray`,
`retrieveSchema`, `getRenderedOptionSchema`, `sanitizeDataForNewSchema`,
`getClosestMatchingOption`,
`getDefaultFieldState`, `retrieveUiSchema`, `uiTitleOption`, `retrieveUiOption`,
`retrieveNestedUiOption`, `uiOptionProps`, `uiOptionNestedProps`,
`retrieveTranslate`, `getFieldTitle`, `getFieldAction`,
`getFieldsValidationMode`, `validateFormValue`, `validateFormValueAsync`,
`getValue`, `getValueSnapshot`

`getValue(form)` returns the live form value without copying it. In a reactive
context it tracks only the properties you read. Treat the returned value as
read-only and use the value commands to update the form. Use
`getValueSnapshot(form)` when you need a detached copy, for example to compare
against a previous value.

Use the standalone `validate(form, handlers)` and `reset(form)` functions
(with the `handlers(form)` form attachment) to validate or reset the whole form.

**Commands:**

- `updateErrors` replaces all field errors with the given validation errors.
- `updateFieldErrors` replaces one field's errors.
- `setFieldState` sets a field's state.
- `validateField` runs field validation for a field config and value.
- `validateAdditionalPropertyKey` checks an additional-property key and stores the result on the field.
- `validateFileList` validates a file list asynchronously and stores the result on the field.
- `setValue` replaces the whole form value and merges schema property defaults; additional-properties defaults are not generated.
- `setValueAtPath` replaces the value at a path.
- `updateValueAtPath` applies an update to the value at a path; annotate the callback parameter to work with a specific value type (e.g. `SchemaObjectValue`), and use it to mutate an object in place.
- `insertArrayItem`, `removeArrayItem`, `moveArrayItem`, and `swapArrayItems` perform structural array changes through the array's `KeyedArray`, so item keys stay in sync. They do nothing when an index is not an integer or is out of bounds.

Use the standalone `reset(form)` function (with the `handlers(form)` form attachment) to restore the form to its `initialValue`.

`setValueAtPath`, `updateValueAtPath`, and the structural array commands record
the replaced value, so the form can resolve the data as it was before the change
and replace defaults left behind by a swapped `dependencies` or
`if`/`then`/`else` branch. `setValue` replaces the whole value and clears the
pending changes instead. Form data cannot be modified directly from outside the
form; use these commands instead.

### `query` vs `command`

In addition to the semantic difference, there is also a behavioral one when used in a **reactive context**.
When a `query` is called, the reactive variables it accesses will be **tracked**.
When a `command` is called, the accessed variables **will not be tracked**.

### `FieldPath` vs `RPath`

Since JavaScript lacks a primitive for **tuples**, the library uses **uniquified paths**.
When a helper needs a canonical path, it converts an `RPath` (a regular array) into a `FieldPath` and caches it in a **prefix tree**.
Each identical path returns the same reference, allowing `FieldPath` to serve as a stable **identifier** or **key** in `Map`/`WeakMap`.

All path-accepting APIs accept an `RPath`. This includes the path helpers
(`getId`, `getSubtreePaths`, `getChildPath`, `getPseudoPath`, and
`getPseudoId`), the value commands (`setValueAtPath`, `updateValueAtPath`,
`insertArrayItem`, `removeArrayItem`, `moveArrayItem`, and `swapArrayItems`),
the error helpers (`getFieldErrors`, `getFieldsErrors`, and `updateFieldErrors`),
and the field-state helpers (`hasFieldState` and `setFieldState`). Except for
`getSubtreePaths`, they register the path internally, so a dynamically generated
path works everywhere. `getSubtreePaths` is a read-only lookup: it returns the
paths already registered in the prefix tree and never registers the path you
pass.

Passing an already registered `FieldPath` (for example `config.path`) skips the
lookup and uses it as-is. `getChildPath` and `getPseudoPath` return a
`FieldPath`, and `getSubtreePaths` and `getErrors` expose them when you need one,
for example as a stable key in a `Map`.

## Internals

The `@sjsf/form` package exports a number of utility functions (e.g. `getComponent`)
that let you safely interact with the form's internal state.
These helpers are the preferred way to read or manipulate internals,
since they are considered part of the supported API and follow semantic versioning.

For advanced cases, you may also access raw internals
by importing symbols from `@sjsf/form/internals` and using them on a `FormState` instance.
The core context symbols, needed to build or inspect a `CoreContext` directly,
are available from `@sjsf/form/core/internals`.

:::caution

Symbols from `@sjsf/form/internals` and `@sjsf/form/core/internals`,
as well as the internal state itself, are not part of the public API.
They may change or be removed in any release, including patch versions.

:::

If you need functionality that isn't covered by the exported helpers,
please [open an issue](https://github.com/x0k/svelte-jsonschema-form/issues/new/choose)
or [start a discussion](https://github.com/x0k/svelte-jsonschema-form/discussions/new/choose)
on GitHub.
This way we can continue improving the API for everyone.
