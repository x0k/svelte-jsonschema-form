The form supports only [JSON Schema Draft-07](https://json-schema.org/draft-07#draft-07) and
[discriminator.propertyName](https://swagger.io/docs/specification/v3_0/data-models/inheritance-and-polymorphism/#discriminator) keyword.

Using converters (`@sjsf/form/converters/draft-2020-12`) and
adapters (`@sjsf/zod4-validator/classic`, `@sjsf/zod4-validator/mini`, `@sjsf/valibot-validator`),
it is possible to generate forms from other formats and sources.
See the <OpenInSandbox client:visible example="Draft 2020-12" /> example for details.

## String formats

Some string formats has special meaning:

- `date-time` - `datetime-local` input type
- `uri` - `url` input type
- `color`, `date`, `time`, `email` - corresponding input type
  - You can use `useDatePickerForDateFormat` function from
    `@sjsf/form/fields/extra-widgets/date-picker` to use `datePickerWidget`
    for `date` format
- `data-url` - file field (with `compat` resolver)

## Reference resolution

The core entry point exports two helpers for local `$ref` values:

```typescript
import { createCoreContext, resolveRef, resolveRefSafe } from "@sjsf/form/core";

const ctx = createCoreContext({ validator, merger, rootSchema });

const schema = resolveRef(ctx, "#/definitions/address");
const maybeSchema = resolveRefSafe("#/definitions/address", rootSchema);
```

`resolveRef` throws when the reference is not local or does not resolve.
`resolveRefSafe` returns `undefined` instead, so it is useful when walking a
schema whose references you do not control. Both helpers accept a [JSON
Pointer](https://datatracker.ietf.org/doc/html/rfc6901) in URI fragment
identifier format and only read own properties.

## Core context

The schema helpers in `@sjsf/form/core` share their dependencies through a
`CoreContext`. Create one when you call those helpers directly:

```typescript
import {
  createCoreContext,
  getDefaultFormState,
  retrieveSchema,
} from "@sjsf/form/core";

const ctx = createCoreContext({
  validator,
  merger,
  rootSchema: schema,
});

const retrieved = retrieveSchema(ctx, schema, formData);
const defaults = getDefaultFormState(ctx, schema, formData);
```

The context stores its dependencies under internal symbols, so a `FormState` can
implement the interface without exposing them as public properties. A `FormState`
can therefore be passed anywhere a `CoreContext` is expected. The symbols
are not part of the `@sjsf/form/core` entry point; import them from
`@sjsf/form/core/internals` if you build or inspect a context directly. The
operations they back are available as free functions with the context as their
first argument:
`isValid(ctx, schema, value)`, `mergeSchemas(ctx, a, b)`,
`mergeAllOf(ctx, schema)`, `isValueDeepEqual(ctx, a, b)`,
`resolveRef(ctx, ref)`, and `getRootSchema(ctx)`. Every core helper that needs
the validator or merger takes the context as its first argument. `resolveRef`
reads the root schema from the context too; `resolveRefSafe` stays a low-level
pointer helper and continues to take the root schema directly.

## Details and limitations

- Library only supports local definition referencing. The value in the `$ref` keyword should be a [JSON Pointer](https://datatracker.ietf.org/doc/html/rfc6901) in URI fragment identifier format.
- `$schema` keyword is ignored
- Some keywords are only involved in validation.
  - `contains`
  - `not`
- `exclusiveMaximum`, `exclusiveMinimum` are not currently passed to input elements.
- `writeOnly`, `contentMediaType` and `contentEncoding` has no special meaning.
- `additionalProperties: false` produces incorrect schemas when used with schema dependencies.
- Properties declared inside the `anyOf`/`oneOf` should not overlap with properties "outside" of the `anyOf`/`oneOf`.
