v4 makes the form own its value and replaces submission with validation. This
guide covers the breaking changes and links to the pages that document the new
APIs. The [form changelog](/changelogs/form/) lists every v4 change.

Upgrade to the latest v3 release and remove deprecated API usage before you
start; v4 removes those APIs.

## Upgrade all packages

Upgrade all `@sjsf/*` packages to v4 together; mixing v3 and v4 packages is
not supported.

## Shared defaults

`createForm` now requires a value handler and a logger. Add both to the defaults
file you spread into every form:

```ts
export { defaultFormValueHandler as valueHandler } from "@sjsf/form/value-handlers/default";
export { createLogger as logger } from "@sjsf/form/loggers/once";
```

Pass the logger factory rather than a shared instance when the logger keeps
per-form state; see [Logger](/form/logger/) for the built-in implementations. If
you create a validator, merger, ID builder, or core context directly, pass the
value handler and logger to it as well.

See [Reusable defaults](/guides/reusable-defaults/), [Logger](/form/logger/),
[Value handler](/form/value-handler/), and [Merger](/form/merger/).

## Form-owned values

The controlled `value` option is gone. Seed the form with `initialValue` and
change it through the value commands from `@sjsf/form`:

```ts
setValue(form, { username: "bob" });
setValueAtPath(form, ["username"], "alice");
updateValueAtPath(form, ["profile"], (profile: SchemaObjectValue) => {
  profile.name = "Alice";
  return profile;
});
```

`SchemaObjectValue` is exported from `@sjsf/form/core`. `Bind` and
`refFromBind` are removed. `keyedArraysMap` is gone; use
`insertArrayItem`, `removeArrayItem`, `moveArrayItem`, and `swapArrayItems` so
item keys stay in sync. Read values with `getValue` (live) or
`getValueSnapshot` (detached), and do not mutate the live value.

In custom components, read `ctx[FORM_VALUE].get()`. Path and error helpers
accept an `RPath`; their `*ByPath` variants (`getIdByPath`, `getPseudoIdByPath`,
`getFieldErrorsByPath`, `getFieldsErrorsByPath`, `updateFieldErrorsByPath`) are
removed.

See [Form state](/form/state/) and
[Programmatic control](/guides/programmatic-control/).

## Validation replaces submission

`form.submission` is now `form.validation`, and the `submission*` options are
`validation*`. The callbacks changed too:

- `onSubmit` / `onSubmitError` / `onSubmissionFailure` → `onValid` / `onInvalid`
  / `onValidationProcessError`; `onReset` is removed.
- `onFieldsValidationFailure` → `onFieldsValidationProcessError`.

`form.submit(e)` and `form.reset(e)` are removed. Call
`validate(form, handlers)` and `reset(form)` yourself, or attach
`handlers(form)` to the `<form>` (as `BasicForm` does) to wire both to the
form's `onValid` / `onInvalid` options:

```svelte
<form novalidate {@attach handlers(form)}>...</form>
```

For custom submit handling, call `validate(form, { onValid, onInvalid })` from
`onsubmit`.

`form.isSubmitted` and `form.isChanged` are also removed. Use
`form.validation.status` (`idle`, `processing`, `success`, or `failed`)
instead. For unsaved changes, capture a value snapshot when the form is created
and compare it with the current snapshot; pass the getter to
`preventPageReload(() => boolean)`.

In v3, `onSubmitError={createFocusOnFirstError()}` focused the first invalid
field. In v4, bind the form when creating the handler
(`createFocusOnFirstError({ form })`) and call it with the submit event:

```svelte
<form
  onsubmit={(e) => {
    e.preventDefault();
    void validate(form, { onInvalid: focusOnFirstError(e) });
  }}
>
```

The `AFTER_SUBMITTED` fields-validation mode flag is now `AFTER_VALIDATED`, and
the `FIELD_SUBMITTED` field-state flag is removed. The `validate(ctx)` /
`validateAsync(ctx, signal)` form-state helpers are now
`validateFormValue(ctx)` / `validateFormValueAsync(ctx, signal)`; call
`validate(form, handlers)` above to trigger validation.

See [Validation](/guides/validation/), [State methods](/form/state/#methods),
[Prevent page reload](/guides/prevent-page-reload/), and
[Focus on first error](/guides/validation/#focus-on-first-error).

## Form layout and themes

The customizable `Form` component is now `Root`, a platform-agnostic layout
slot. Render the actual `<form>` with `BasicForm` or your own element.

- `ui:options.form` → `ui:options.root`; `formAttributes()` →
  `rootAttributes()`.
- The `"form"` UI component key and pseudo-element are now `"root"`; rename
  per-path `ui:components` / `ui:options` overrides and derived IDs keyed on it.
- Move form element attributes (`action`, `method`, `novalidate`, …) to
  `BasicForm` or your `<form>`.
- The `root` component no longer exposes a `ref` binding; bind the `<form>`
  element through `BasicForm` or your own markup.
- In a theme, rename `form.svelte` to `root.svelte` and export `root` instead
  of `form`. Custom themes must also handle the required
  `checkboxWidget.mustBeChecked` prop (render the marker and set native
  `required` only when it is `true`) and require `showMeta` in
  `multiFieldTemplate` / `optionalMultiFieldTemplate`.

daisyUI 5 now uses the Cally date picker for `datePickerWidget`. Replace
`daisyui5CallyDatePickerWidget` and the `cally-date-picker*` imports with
`datePickerWidget` and `date-picker*`. Pikaday options and the `pikaday` peer
dependency are removed. Skeleton 4, shadcn 4, and SVAR should replace
`skeleton4DateRangePickerWidget`, `shadcn4DateRangePickerWidget`, and
`svarDateRangePickerWidget` with `dateRangePickerWidget`.

See [Theme](/form/theme/).

## Validators and core helpers

Validators no longer receive the root schema per call: remove the `rootSchema`
argument from `isValid`, `validateFormValue`, and `validateFormValueAsync`.
The root schema is bound when the validator is created. Treat form values as
`ReadonlySchemaValue` and copy them before applying any transformation.

Ajv, schemasafe, ata, and cfworker now compile the root schema when the
validator is created, so a schema that violates its meta-schema fails during
form creation instead of at first validation.

Replace `LegacyValidatorOptions` with `validatorRetriever` in the Ajv,
schemasafe, ata, and Hyperjump validators, and
`setupFormValidator` / `setupAsyncFormValidator` with `adapt` / `adaptAsync`
in the Zod and Valibot validators.

Core schema helpers that need form context now take a `CoreContext` (or a
`FormState`) as their first argument. Build one with `createCoreContext`; see
[Core context](/form/schema/#core-context). Import the helpers from
`@sjsf/form/core`, not the main entry point; the predicates are now
`isSelectSchema`, `isMultiSelectSchema`, `isFilesArraySchema`,
`isConstantValueSchema`, and `isFixedItemsSchema`.

Replace `FORM_VALIDATOR`, `FORM_MERGER`, and `FORM_SCHEMA` with the `CORE_*`
symbols from `@sjsf/form/core/internals` (`FORM_SCHEMA` → `CORE_ROOT_SCHEMA`).
Drop the `expandAllBranches` argument from schema-resolution calls, and remove
the `validateByRetrievedSchema` option (call `retrieveSchema` in your validator
extension instead). Rename `Experimental_DefaultFormStateBehavior` to
`DefaultFormStateBehavior`, `Experimental_ArrayMinItems` to `ArrayMinItems`, and
the `experimental_defaultFormStateBehavior` parameter to
`defaultFormStateBehavior`. Change
`omitExtraData(validator, merger, rootSchema, value)` to
`omitExtraData(ctx, value)`, and pass the root schema to `createCoreContext`
instead of relying on `getDefaultFormState`'s schema argument.

See [Validator](/form/validator/) and
[Core context](/form/schema/#core-context).

## SvelteKit integration

`@sjsf/sveltekit` (the SvelteKit 2 integration) is removed; use
[`@sjsf/sveltekit3`](/integrations/form-actions/) for SvelteKit 3. With
`@sjsf/sveltekit3`, `createAction`, `createFormHandler`, and
`createServerValidator` now require `valueHandler` and `logger`; spreading your
updated defaults is enough. Update client form options and callbacks to the
validation API.

See [Form actions](/integrations/form-actions/) and
[Remote functions](/integrations/remote-functions/).

## Custom components

- Enum options: `FormEnumOption.mappedValue` is required. Create options with
  `createMappedOption()` from `@sjsf/form/options.svelte`.
- The default enum mapper is `StringEnumValueMapperBuilder`. Select
  `IdEnumValueMapperBuilder` through the `enumValueMapperBuilder` UI option for
  object values or values that do not map to unique strings; `idMapper()` is
  removed.
- Add the now-required widget/context fields: `Options.mapper`,
  `SingleSelectOptions.clearable`, `SingleSelectOptions.mapped`,
  `MultiSelectOptions.mapped`, and `ArrayContextOptions.setValue`.
- `Config.value` is now required.
- Replace `.value` with `.current` from `singleOption()` / `multipleOptions()`,
  and `hasInitialValue` with `clearable`.
- Combination fields own their title, description, and action. Put
  branch-specific options and components in the branch UI schema; parent
  `ui:options` / `ui:components` apply to the field that renders the shared
  `properties`.
- Combination field deep imports moved under `fields/combination`:
  `@sjsf/form/fields/any-of` → `@sjsf/form/fields/combination/any-of`,
  `@sjsf/form/fields/one-of` → `@sjsf/form/fields/combination/one-of`, and
  `@sjsf/form/fields/combination` → `@sjsf/form/fields/combination/combination`.
- `booleanSelectField` no longer reads `oneOf`; declare an `enum` or use a
  custom field.
- Custom ID builders must implement `idPrefixName()`; `resolveIdPrefixName`
  is removed.

See [Custom components](/guides/custom-components/) and
[UI options](/form/ui-schema/#ui-options).

## Behavior changes

These changes may pass the type checker but alter runtime behavior:

- A schema with both `oneOf` and `anyOf` now renders from `anyOf` everywhere.
  Remove one keyword or make the lists agree.
- `dependencies` and `if`/`then`/`else` branches now drop stale defaults when
  the selected branch changes. Review forms that depend on the old values.
- Multi-type schemas now render through `unionField` with a type selector;
  customize it with the `union` UI schema keyword. A single nullable type and
  values pinned by `enum` or `const` keep their plain field.

See [Dynamic forms](/guides/dynamic-forms/) and
[Multiple types](/form/schema/#multiple-types).

## Removed APIs and imports

The [v4 changelog](/changelogs/form/) lists every removed API and its
replacement. Common removals are `createOptions` → `createFormOptions`,
`setFormContext2` → `setFormContext`, `UNDEFINED_ID` → `EMPTY_VALUE`, and
`KeyedArray2` → `KeyedArray`.

Deep imports changed too: `MapLike` moved from `@sjsf/form/lib/memoize` to
`@sjsf/form/lib/map`.

Run your type checker and tests, then smoke-test value editing, submit, reset,
dynamic branches, arrays, file uploads, and your SvelteKit actions.

If something is still unclear, ask in
[GitHub Discussions](https://github.com/x0k/svelte-jsonschema-form/discussions).
