Before migrating, make sure you are using the latest version of SJSF and
that you are not using any deprecated APIs.

## Form-owned value

The controlled `value` form option has been removed. The form owns its value:
seed it with `initialValue`, replace it with `setValue(form, value)`, edit it
with `setValueAtPath`, `updateValueAtPath`, and the array commands, and restore
`initialValue` with `reset(form)`. `Bind` and `refFromBind` are removed from
`@sjsf/form/lib/svelte.svelte`.

The `keyedArraysMap` option is removed. Use `insertArrayItem`,
`removeArrayItem`, `moveArrayItem`, and `swapArrayItems` to change arrays so
item keys stay in sync.

The internal `FORM_VALUE` entry is now a `FormValueStore`: read with
`ctx[FORM_VALUE].get()` and write through its `replace`, `setAtPath`,
`updateAtPath`, and `updateArrayAtPath` methods. Custom components that used
`ctx[FORM_VALUE]` as a raw value must add `.get()`.

The value commands accept an `RPath` (a plain array). Passing a registered
`FieldPath` skips the lookup and uses it as-is.

Use `getValue(form)` for a live, non-copying read of the form value. In a
reactive context it tracks only the properties you read. It is typed as
`ReadonlySchemaValue | undefined`, as are the core helpers that only read form
data, such as `retrieveSchema`, `getClosestMatchingOption`, `isValid`, and
`isValueDeepEqual`. Mutable form values remain assignable. Use
`getValueSnapshot(form)` when you need a detached copy.

`getIdByPath`, `getPseudoIdByPath`, and the `ByPath` variants of the error and
field-state helpers are removed. `getId`, `getPseudoId`, `getSubtreePaths`,
`getChildPath`, `getPseudoPath`, `getFieldErrors`, `getFieldsErrors`,
`updateFieldErrors`, `hasFieldState`, and `setFieldState` now accept an `RPath`;
except for `getSubtreePaths`, they canonicalize it internally, and passing a
registered `FieldPath` skips the lookup. `getSubtreePaths` is a read-only
lookup: it returns the paths already registered in the prefix tree and does not
register the path you pass.

```ts
import {
  insertArrayItem,
  reset,
  setValue,
  setValueAtPath,
  updateValueAtPath,
} from "@sjsf/form";
import type { SchemaObjectValue } from "@sjsf/form/core";

setValue(form, { username: "bob" });
setValueAtPath(form, ["username"], "alice");
updateValueAtPath(form, ["profile"], (profile: SchemaObjectValue) => {
  profile.name = "Alice";
  return profile;
});
insertArrayItem(form, ["items"], "new item");
reset(form);
```

## Validator interface changes

The root schema is now bound at validator creation time instead of being
passed on every call. The `rootSchema` parameter has been removed from
`Validator.isValid`, `FormValueValidator.validateFormValue` and
`AsyncFormValueValidator.validateFormValueAsync`.

`Validator.isValid` now receives `ReadonlySchemaValue | undefined` instead of
`SchemaValue | undefined`. Validators must treat the value as read-only and
copy it before applying any transformation.

## Schema errors now surface at form creation

Validators compile the schema eagerly when created. A schema that does not
satisfy its dialect's meta-schema (for example, a `discriminator` whose
property is missing from the branches' `required`, or an empty tuple
`items: []` in draft-07) now fails at form creation instead of at first
validation. Fix such schemas to be spec-compliant.

## Value comparison and copying moved out of the merger

`Merger` no longer implements `isValueDeepEqual`; it only merges schemas and
`allOf` compositions. Value comparison and the copy taken before an in-place
update are now a required `FormOptions` service:

```typescript
import { createForm } from "@sjsf/form";
import { defaultFormValueHandler } from "@sjsf/form/value-handlers/default";

const form = createForm({
  // ...
  valueHandler: defaultFormValueHandler,
});
```

Reusable defaults can re-export it as before:

```typescript
export { defaultFormValueHandler as valueHandler } from "@sjsf/form/value-handlers/default";
```

`CoreContext` still carries a value handler under `CORE_VALUE_HANDLER`, and
`createCoreContext` requires one; a `FormValueHandler` can be passed because it
extends `ValueHandler`. Custom mergers no longer implement or forward
`isValueDeepEqual` or `copyForChange`; pass a custom `FormValueHandler` to
`createForm` instead. See [Value handler](/form/value-handler/).

`ValueDeepComparator` now takes `ReadonlySchemaValue | undefined` for both
arguments, so it can compare values returned by `getValue`. A custom comparison
must not mutate its arguments.

## Logger

`createForm` now requires a `logger` service. It receives schema-resolution
warnings, `<Field>` development diagnostics, and validator failures. Re-export
the recommended logger from your defaults:

```typescript
export { createLogger as logger } from "@sjsf/form/loggers/once";
```

Pass the factory to `createForm` so each form keeps its own record of the
messages it has already reported:

```typescript
import { createForm } from "@sjsf/form";
import { createLogger } from "@sjsf/form/loggers/once";

const form = createForm({
  // ...
  logger: createLogger,
});
```

Use `logger` from `@sjsf/form/loggers/noop` to silence output. The validator,
merger, id builder, and `createCoreContext` now require the logger instance;
`createForm` passes it to them automatically when you use the factory above.

## Schema resolution internals

The unused `expandAllBranches` parameter was removed from the schema-resolution
functions in `@sjsf/form/core`. Drop the argument from any direct calls.

Core schema helpers now take a shared `CoreContext` as their first argument
instead of `validator`, `merger`, `rootSchema`, and value-comparison arguments.
Build one with
`createCoreContext({ validator, merger, valueHandler, rootSchema, logger })`:

```typescript
// Before
retrieveSchema(validator, merger, schema, rootSchema, formData);

// After
import { createCoreContext, retrieveSchema } from "@sjsf/form/core";

const ctx = createCoreContext({
  validator,
  merger,
  valueHandler,
  rootSchema,
  logger,
});
retrieveSchema(ctx, schema, formData);
```

`FormState` extends `CoreContext`, so a form state can be passed to any core
helper as its context. The form-state re-exports of `retrieveSchema`,
`sanitizeDataForNewSchema`, `getClosestMatchingOption` and
`getRenderedOptionSchema` were removed; import them from `@sjsf/form/core`.
`getRenderedOptionSchema` is now exported from there. `getDefaultFieldState`
remains a form-state query.

The schema predicates were renamed to say what they inspect:

```typescript
// Before
import {
  isSelect,
  isMultiSelect,
  isFilesArray,
  isSchemaOfConstantValue,
  isFixedItems,
} from "@sjsf/form/core";

// After
import {
  isSelectSchema,
  isMultiSelectSchema,
  isFilesArraySchema,
  isConstantValueSchema,
  isFixedItemsSchema,
} from "@sjsf/form/core";
```

The context operations are available as free functions that take the context
first: `isValid(ctx, schema, value)`, `mergeSchemas(ctx, a, b)`,
`mergeAllOf(ctx, schema)`, `isValueDeepEqual(ctx, a, b)`,
`resolveRef(ctx, ref)`, and `getRootSchema(ctx)`.

The context symbols are not part of the `@sjsf/form/core` entry point. If you
build or inspect a `CoreContext` directly, import `CORE_VALIDATOR`,
`CORE_MERGER`, `CORE_VALUE_HANDLER`, and `CORE_ROOT_SCHEMA` from
`@sjsf/form/core/internals`.

`FORM_VALIDATOR`, `FORM_MERGER`, and `FORM_SCHEMA` were removed from
`@sjsf/form/internals`; they were aliases of the corresponding `CORE_*`
symbols. Use the `CORE_*` names from `@sjsf/form/core/internals` instead.

`getDefaultFormState` no longer falls back to the schema it receives as the
root schema. A caller that omitted `rootSchema` so that a self-referencing
subschema resolved against itself must pass that subschema as `rootSchema` when
creating the context.

## Read-only value types

Read-only form values are represented by
`ReadonlySchemaValue = DeepReadonly<SchemaValue>`. Core helpers that only read
form data accept it, so `getValue` results can be passed directly to
`retrieveSchema`, `getClosestMatchingOption`, `isValid`, and
`isValueDeepEqual`.

`DeepPartial` and `DeepReadonly` now leave class instances intact instead of
mapping their members. This matters when `SchemaValues` is augmented with
types such as `File` or `Date`: `DeepPartial<File>` is still `File`, so
`initialValue` and `setValue` accept such values without casts. Functions are
preserved too.

## Enum options

`FormEnumOption.mappedValue` is now required. Use `createMappedOption()`
from `@sjsf/form/options.svelte` instead of building objects manually.

The default mapper is now `StringEnumValueMapperBuilder` (better autofill).
It accepts primitive values only and throws when two values map to the same
string, such as `1` and `"1"` or `null` and `"null"`. To map object values or
enum values that are not string-unique, restore ID-based mapping:

```ts
"ui:options": {
  enumValueMapperBuilder: (ctx) =>
    new IdEnumValueMapperBuilder(ctx),
}
```

## Widget options

`Options.mapper`, `SingleSelectOptions.clearable`, `SingleSelectOptions.mapped`,
`MultiSelectOptions.mapped`, and `ArrayContextOptions.setValue` are now required.
The `singleOption()` and
`multipleOptions()` helpers no longer return a deprecated `.value` property —
use `.current` instead. `SingleSelectOptions.hasInitialValue` has been removed
(use `clearable` instead).

## Removed deprecated APIs

- `createOptions()` — use `createFormOptions()`.
- `idMapper()` — use the `enumValueMapperBuilder` UI option with `IdEnumValueMapperBuilder`.
- `isSchemaExpandable()` — use `isObjectSchemaExpandable()`.
- `UNDEFINED_ID` — use `EMPTY_VALUE` instead.
- `FormErrorsMap` type — read errors through `getErrors` / `getFieldErrors`, or use `SvelteMap<FieldPath, string[]>` directly.
- `setFormContext2` — use `setFormContext`.
- `KeyedArray2` type — use `KeyedArray`.
- `MapLike` type — moved from `@sjsf/form/lib/memoize` to `@sjsf/form/lib/map`, which also exports `getOrInsertComputed()`.
- `validateByRetrievedSchema` option — use `retrieveSchema` from `@sjsf/form/core`.
- `DEFAULT_AUGMENT_SUFFIX` — use `idAugmentations` on `FragmentSchemaOptions`.
- `augmentSuffix` on `FragmentSchemaOptions` — use `idAugmentations`.
- `Query.result` — use `Query.current`.
- `getSelectOptionValues()` — use `getSelectOptionValuesSafe()`.
- `@sjsf/form/fields/any-of` — use `@sjsf/form/fields/combination/any-of`.
- `@sjsf/form/fields/one-of` — use `@sjsf/form/fields/combination/one-of`.
- `@sjsf/form/fields/combination` — use `@sjsf/form/fields/combination/combination`.
- `Config.value` is now required.
- `removeVirtualAdditionalProperties()` — removed from `@sjsf/form/validators/properties`.
- `createVirtualAdditionalPropertiesRemover()` — removed from `@sjsf/form/validators/properties`.
- `createPatternPropertyKeyValidator()` `error` parameter no longer accepts a string — pass a function `(ctx) => string` instead.

## Validator packages

- `LegacyValidatorOptions` (`validateFunctions`, `augmentSuffix`, `ast`) removed — use
  `validatorRetriever` directly (ajv8, schemasafe, ata, hyperjump).
- `setupFormValidator` removed — use `adapt` (zod4, valibot).
- `setupAsyncFormValidator` removed — use `adaptAsync` (zod4, valibot).

## Theme packages

- `skeleton4DateRangePickerWidget` removed — use `dateRangePickerWidget`.
- `shadcn4DateRangePickerWidget` removed — use `dateRangePickerWidget`.
- `svarDateRangePickerWidget` removed — use `dateRangePickerWidget`.
- `daisyui5CallyDatePickerWidget` removed — `datePickerWidget` now renders the
  Cally date picker.
- `@sjsf/daisyui5-theme/extra-widgets/cally-date-picker` and
  `@sjsf/daisyui5-theme/extra-widgets/cally-date-picker-include` removed — use
  `@sjsf/daisyui5-theme/extra-widgets/date-picker` and
  `@sjsf/daisyui5-theme/extra-widgets/date-picker-include`.
- `daisyui5PikadayCalendar` and `daisyui5PikadayCalendarOptions` removed — the
  Pikaday date picker and its `pikaday` peer dependency are gone; use the
  Cally options (`daisyui5CallyCalendar*`) instead.

## SvelteKit packages

- `@sjsf/sveltekit` (SvelteKit 2 integration) removed — use `@sjsf/sveltekit3`.
- `@sjsf/sveltekit/*` imports → `@sjsf/sveltekit3/*`.
- `$lib` imports → `#lib` imports with explicit `.js` extensions.

## Form layout (`Form` → `Root`)

The customizable `form` foundational component is replaced by a
platform-agnostic `root` layout slot:

- `Form` export → `Root` export; theme `form.svelte` files → `root.svelte`
  (layout `<div>`, no form element attributes).
- `BasicForm` now renders a plain web `<form>` with the `handlers(form)`
  attachment and `<Root><Content /><SubmitButton /></Root>` inside.
- `ui:options.form` (`HTMLFormAttributes`) → `ui:options.root`
  (`HTMLAttributes<HTMLDivElement>`); pass form element attributes
  (`action`, `method`, `novalidate`, …) directly to `BasicForm` or your
  own `<form>` element instead.
- `formAttributes()` helper removed — use `rootAttributes()`.
- Custom components resolving `"form"` via `getComponent` or overriding it
  through `ui:components` must be renamed to `"root"`.

## Validation replaces submission

- `form.submission` → `form.validation`;
  `submissionCombinator/DelayedMs/TimeoutMs` →
  `validationCombinator/DelayedMs/TimeoutMs`.
- `onSubmit(value, e)` / `onSubmitError(result, e, form)` /
  `onSubmissionFailure(state, e)` / `onReset(e)` →
  `onValid(value)` / `onInvalid(result)` / `onValidationProcessError(error)`;
  `onFieldsValidationFailure` → `onFieldsValidationProcessError`.
- `form.submit(e)` / `form.reset(e)` removed — use the standalone
  `validate(form, handlers)` / `reset(form)` functions with the
  `handlers(form)` form attachment.
- `AFTER_SUBMITTED` → `AFTER_VALIDATED`;
  `validate(ctx)` / `validateAsync(ctx, signal)` →
  `validateFormValue(ctx)` / `validateFormValueAsync(ctx, signal)`.
- `preventPageReload({ isChanged })` → `preventPageReload(() => boolean)`
  (getter callback); compare the value snapshot with the initial value
  to detect unsaved changes.
- `form.isSubmitted` / `form.isChanged` removed.

## Focus on first error

`createFocusOnFirstError` is curried around the submit event so the
returned callback fits `validate(form, { onInvalid })`:

```svelte
<script lang="ts">
  import { createForm, setFormContext, validate } from "@sjsf/form";
  import { createFocusOnFirstError } from "@sjsf/form/focus-on-first-error";

  const form = createForm({ ... });
  setFormContext(form);
  const focusOnFirstError = createFocusOnFirstError({ form });
</script>

<form
  onsubmit={(e) => {
    e.preventDefault();
    void validate(form, { onInvalid: focusOnFirstError(e) });
  }}
  novalidate
>
  <!-- ... -->
</form>
```
