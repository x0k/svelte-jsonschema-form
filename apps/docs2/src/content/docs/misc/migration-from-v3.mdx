Before migrating, make sure you are using the latest version of SJSF and
that you are not using any deprecated APIs.

## Validator interface changes

The root schema is now bound at validator creation time instead of being
passed on every call. The `rootSchema` parameter has been removed from
`Validator.isValid`, `FormValueValidator.validateFormValue` and
`AsyncFormValueValidator.validateFormValueAsync`.

## Schema errors now surface at form creation

Validators compile the schema eagerly when created. A schema that does not
satisfy its dialect's meta-schema (for example, a `discriminator` whose
property is missing from the branches' `required`, or an empty tuple
`items: []` in draft-07) now fails at form creation instead of at first
validation. Fix such schemas to be spec-compliant.

## Schema resolution internals

The unused `expandAllBranches` parameter was removed from the schema-resolution
functions in `@sjsf/form/core`. Drop the argument from any direct calls.

## Enum options

`FormEnumOption.mappedValue` is now required. Use `createMappedOption()`
from `@sjsf/form/options.svelte` instead of building objects manually.

The default mapper is now `StringEnumValueMapperBuilder` (better autofill).
To restore ID-based mapping:

```ts
"ui:options": {
  enumValueMapperBuilder: () => new IdEnumValueMapperBuilder(),
}
```

## Widget options

`Options.mapper`, `SingleSelectOptions.clearable`, `SingleSelectOptions.mapped`,
`MultiSelectOptions.mapped`, and `ArrayContextOptions.setValue` are now required.
The `singleOption()` and
`multipleOptions()` helpers no longer return a deprecated `.value` property —
use `.current` instead. `SingleSelectOptions.hasInitialValue` has been removed
(use `clearable` instead).

## Removed deprecated APIs

- `createOptions()` — use `createFormOptions()`.
- `idMapper()` — use `resolveEnumValueMapperBuilder()` + `builder.build()`.
- `isSchemaExpandable()` — use `isObjectSchemaExpandable()`.
- `UNDEFINED_ID` — use `EMPTY_VALUE` instead.
- `FormErrorsMap` type — use `SvelteMap<FieldPath, string[]>` directly.
- `setFormContext2` — use `setFormContext`.
- `KeyedArray2` type — use `KeyedArray`.
- `validateByRetrievedSchema` option — use `retrieveSchema` from `@sjsf/form/core`.
- `DEFAULT_AUGMENT_SUFFIX` — use `idAugmentations` on `FragmentSchemaOptions`.
- `augmentSuffix` on `FragmentSchemaOptions` — use `idAugmentations`.
- `Query.result` — use `Query.current`.
- `getSelectOptionValues()` — use `getSelectOptionValuesSafe()`.
- `@sjsf/form/fields/any-of` — use `@sjsf/form/fields/combination/any-of`.
- `@sjsf/form/fields/one-of` — use `@sjsf/form/fields/combination/one-of`.
- `@sjsf/form/fields/combination` — use `@sjsf/form/fields/combination/combination`.
- `Config.value` is now required.

## Validator packages

- `LegacyValidatorOptions` (`validateFunctions`, `augmentSuffix`, `ast`) removed — use
  `validatorRetriever` directly (ajv8, schemasafe, ata, hyperjump).
- `setupFormValidator` removed — use `adapt` (zod4, valibot).
- `setupAsyncFormValidator` removed — use `adaptAsync` (zod4, valibot).

## Theme packages

- `skeleton4DateRangePickerWidget` removed — use `dateRangePickerWidget`.
- `shadcn4DateRangePickerWidget` removed — use `dateRangePickerWidget`.
- `svarDateRangePickerWidget` removed — use `dateRangePickerWidget`.
