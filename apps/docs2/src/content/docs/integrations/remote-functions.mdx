## Submission encoding

By default, enhanced submissions send the form's own controls — the same parts a native
submission would send — so the server parses both identically. No JSON
serialization of the form value is involved.

Pass `useJsonChunks` to `connect()` to submit the form data as JSON. This needs JavaScript:
without it the browser submits the fields on its own, so the submission may look different from the JSON one.

Fields whose schema declares no `type` are rejected unless the validator is
given a `convertUnknownEntry` to handle them:

```ts
import type { FieldValue } from "@sjsf/form";

const validator = createServerValidator({
  ...defaults,
  schema,
  convertUnknownEntry: ({ value }) => value as FieldValue,
});
```

## Known issues

- `experimental.async` does not apply to dependency code -
  [issue](https://github.com/sveltejs/kit/issues/14788).

  Add this to your `vite.config.js`

  ```js
  optimizeDeps: {
    exclude: ['@sjsf/form', '@sjsf/sveltekit3/rf/client'],
  }
  ```

- The `form.value` type on the client side is `unknown` because the `RemoteForm`
  type does not include information about the validator's output type.
  Specify the type via `connect` generic: `createForm(await connect<FormValue>(...))`.
