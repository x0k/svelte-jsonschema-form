Remove a `dependencies` or `if`/`then`/`else` branch's stale default when the selected branch swaps in a different one, then let the normal defaults pass write the new value.

A value that still holds what the old branch computes as the key's default is removed even when it came from `initialValue`; a value edited away from it is kept. Both branches must declare the key, either with `default` or `const` on the property's schema or in the level's own `default` object, before a difference can replace the value. The comparison uses the computed defaults of each branch, so nested leaf defaults, an `items` default repeated to `minItems`, and the placeholders a required object, array, or boolean produces participate; none of them declares a key on its own. `null` is a declaration like any other, a custom `isValueDeepEqual` comparer governs the comparison, and a change at a parent path protects every value inside it. Values are matched per key of the level that declares the default, and array items are not searched. See the dynamic forms guide for the full replacement rules.

Add the required `FormMerger.dropStaleDefaults` hook. The built-in modern and legacy mergers implement it. Custom `FormMerger` implementations must delegate `dropStaleDefaults` to the new exported helper or implement the pass themselves. The helper expects the `FormMerger` instance so it computes defaults the same way `mergeFormDataAndSchemaDefaults` does. It returns the settled form data together with the value and schema of every path it dropped, so the form can restore an unfilled value and judge a replacement at its own key. The options carry the pass's original form data and resolved schema, the canonical paths it has already dropped together with the factory that produces them, and the fill's `initialDefaultsGenerated` flag, so repeated searches within one pass stay consistent.

Add the required `FormMerger.copyForChange` hook so a custom merger can copy the value types it stores. The built-in mergers copy arrays and plain objects recursively and keep other values by reference. A merger whose form data contains custom containers such as `Map` or `Set` can override `copyForChange` and delegate nested values to the exported helper.
